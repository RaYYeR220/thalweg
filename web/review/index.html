Review queue

Only a person can issue a warning.

The station drafts a flood warning when its nowcast says the threshold is likely within three hours. The Step Functions execution then pauses on a task token (waitForTaskToken). Signing here resumes it and publishes the warning; rejecting closes it. The agent has no tool for either, and an unsigned draft expires after six hours.

Reviewer

needed to sign or reject

Judges: the passcode is in the submission form. It stays in this tab and is sent only with a signature or a rejection.

What happens

  1. Sign: the API checks the passcode (403 if wrong) and that the warning is still a draft (409 if not), then calls SendTaskSuccess. The paused execution resumes, marks it SIGNED and publishes it to public/warnings.json.
  2. Reject: SendTaskFailure; the execution marks it REJECTED with your note.
  3. Nobody acts: after six hours the task token times out and the draft is EXPIRED.
